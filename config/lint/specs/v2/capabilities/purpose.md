# Purpose: the capabilities page

| Reader | Comes with the question | Leaves for |
|---|---|---|
| Person, the operator; not an engineer | What do I have for this use, and what does each thing do for me? | A tool page or a skill, by its name in a row |
| An agent at the start of a task | Which skill does this job, and is the tool it needs set up? | The skill, then the tool page in `Tools it needs` |
| A new person who installed Foxrun | What is on this Mac, and what is not placed yet? | `Not placed yet`, by its links in `Contents` |

**In ten seconds the page must answer:** what uses there are, and where the tools and skills of one use are.

## The check against version 1

| The page must | Version 1 | Version 2 |
|---|---|---|
| Show the way to each group at the top | A table of uses came after the count block | `Contents` is the first section: topic, then subtopics, with links |
| Say what a column lists | `Needs` had no explanation | `Tools it needs`, and one line on how to read a row |
| Say what a needed tool is | A bare id: `datadoe` | The plain name, a link, and a few words: DataDoe, with its own line |
| Name no business on the system page | The system page listed skills named for a business | The lint forbids it; the page counts them and lists none |
| Keep long gap lists out of the way | Four blocks under one heading | One heading for each list, each with a link in `Contents` |
